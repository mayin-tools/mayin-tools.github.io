Vercel vs Netlify：先看框架和发布流程，再看平台名气

两者都能把 Git 仓库连接到构建和部署流程，也都提供预览环境。真正影响选择的通常是项目框架、团队怎样评审改动、是否依赖函数，以及你想把多少部署细节交给平台。

先看结论

两者都适合现代前端部署和预览。Next.js 深度工作流通常优先 Vercel；更通用的静态站、Jamstack 与 Netlify 生态需求可以优先 Netlify，再按构建、函数和团队权限实测。

Vercel 更适合什么情况

如果项目围绕现代前端框架构建，尤其团队已经习惯“每个分支或 Pull Request 都有可分享预览”，Vercel 的部署体验会很顺。不要把它理解成只能放静态网页，它更像围绕前端应用交付设计的平台。

Netlify 更适合什么情况

Netlify 同样提供基于 Git 的构建和 Deploy Preview，并强调在正式发布前让团队查看、评论和验证改动。对于静态站、Jamstack 工作流以及希望把预览、表单或函数放在一个平台里的团队，它依然是成熟选择。

选择时先比较这四件事

先看框架和构建流程，再看环境变量如何区分预览与生产、团队如何评审 Preview、项目是否依赖平台函数或边缘能力。价格应该最后结合真实用量算，而不是只比较首页上的免费额度。

迁移前不要忽略这些细节

迁移平台前先列出域名、DNS、环境变量、重定向、构建命令、函数、缓存规则和分析脚本。真正容易出问题的往往不是页面本身，而是这些部署外围配置。
