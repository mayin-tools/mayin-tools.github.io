域名、网络与安全

Let's Encrypt 是什么？免费证书真正要管的是自动续期

Let's Encrypt 是公益性质的证书颁发机构，通过 ACME 协议让网站自动申请和续期 TLS 证书。它解决的是公开网站 HTTPS 证书问题，不等于服务器本身已经安全。

访问 Let's Encrypt 官方网站 ↗将打开 letsencrypt.org

最重要的不是第一次申请，而是自动续期

证书有有效期，生产网站不应依赖管理员临到期时手动操作。通常应让 Certbot、Caddy、托管平台或主机商自动完成申请和续期，并定期检查续期任务是否真正成功。

证书自动化的价值在于“以后不用人为记得续”。如果服务器或托管平台已经提供自动申请和续期，优先用平台支持的方式；自己维护时，则要定期确认续期任务是否真的执行、域名验证方式是否仍然可用，以及证书更新后服务是否成功重新加载。

域名验证决定你怎么拿到证书

常见验证方式会证明你控制域名或对应 Web 服务。使用反向代理、CDN、多服务器或通配符证书时，DNS 验证通常更灵活，但也要保护 DNS API 凭据，避免为了自动化给过大权限。

有 HTTPS 不代表网站整体安全

TLS 证书主要用于建立加密连接和验证域名。它不会替你修补服务器漏洞、阻止弱密码、清理恶意脚本或保护后台账号，所以仍要单独处理系统更新、访问控制和备份。

什么时候可能选择其他证书方案

绝大多数公开网站使用 Let’s Encrypt 已足够。若组织有特殊企业合规、私有 PKI、内部设备身份或特定支持合同要求，则可能需要另外的证书服务。

普通网站的 HTTPS 场景里，Let’s Encrypt 往往已经足够；真正需要比较其他方案的情况，通常是企业内部流程、特殊证书类型、集中证书管理或厂商支持要求。不要因为证书免费就忽略运维责任，也不要因为付费就默认安全性一定更高。

免费证书真正要验证的是续期和故障恢复

Let’s Encrypt 证书有效期较短，所以正确做法不是“每隔几个月手动续一次”，而是让 ACME 客户端自动申请和续期。部署完成后应主动测试一次续期流程，确认防火墙、DNS、Web 服务器和定时任务不会在证书快到期时突然阻塞。

如果站点前面还有 CDN、负载均衡或反向代理，要明确证书到底终止在哪一层。有时浏览器看到的是 CDN 证书，而源站证书已经过期，平时看不出来，直到回源或配置变化才暴露问题。

生产环境最好配证书到期监控和告警。证书自动化本身并不复杂，但一旦失效会直接影响用户访问，所以值得把“能自动续、续期失败能被发现”作为上线标准。
