数据与 SEO

PageSpeed Insights 怎么看？先分清真实用户数据和实验室测试

PageSpeed Insights（PSI）可以快速检查网页体验，但一个分数不能代表网站长期表现。看报告时，先分清真实用户数据和本次实验室测试，再决定优先修什么。

访问 PageSpeed Insights 官方网站 ↗将打开 pagespeed.web.dev

真实用户数据和实验室数据不是同一回事

真实用户数据来自一段时间内符合条件的 Chrome 用户访问，反映实际设备与网络环境；Lighthouse 实验室测试则是在模拟条件下单次运行，适合定位技术问题。两者不同并不意味着其中一个“错了”。

PageSpeed Insights 最容易被误用成“追求 100 分”的工具。真正应该先分清的是实验室数据和真实用户数据：前者方便复现问题，后者更接近实际访客体验，两者回答的问题不同。

Core Web Vitals 优先看用户真正感受到的问题

LCP 关注主要内容加载，INP 关注交互响应，CLS 关注布局跳动。优化时要找到造成指标变差的真实组件，例如过大的首屏图片、阻塞脚本、慢后端或没有尺寸的媒体元素，而不是只追求评分颜色。

看到某个指标差时，先定位是图片、字体、脚本、服务器响应还是布局变化造成，不要只按工具建议机械删除资源。很多优化会牵涉广告、分析、业务组件和第三方服务，需要权衡实际价值。

单次分数波动很正常

实验室测速会受到测试节点、服务器状态和第三方资源影响。修改前后最好重复测试，并结合浏览器开发者工具或其他监测手段验证。不要因为一次 98 分变成 95 分就做没有业务价值的改动。

移动端和桌面端结果可能差很多，因为设备性能和网络假设不同。对主要流量来自手机的网站，应优先关注移动端真实体验，而不是只拿高性能桌面环境做判断。

性能优化也要考虑转化和功能

移除所有脚本当然可能让页面更快，但如果同时破坏支付、登录或必要分析就没有意义。优先优化体积大、阻塞明显且用户价值低的资源。

优化后要重新测试并观察一段时间的真实用户数据。一次 Lighthouse 分数提升并不代表所有用户立刻变快，缓存、发布节奏和流量分布都会影响最终结果。
